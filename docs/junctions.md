# Типы перекрёстков и их логика

Все типы описываются одним форматом раскладки (`smart_intersection/layout.py`): 1–4 полосы «к перекрёстку» и «от него»
на каждом плече, у каждой входящей полосы список разрешённых движений и вид управления (`junction`: `signal` или
`roundabout`). Готовые типы — `presets()` / `JUNCTION_TYPES`; каталог с описаниями отдаёт `GET /layout/junction-types`,
в конструкторе он лежит на вкладке **Cities → Junction types**.

## Общие правила

**Движение правостороннее.** Полоса 0 — у осевой линии, дальше к обочине. Движение `right` — на ближайшую справа дорогу,
`left` — слева, `straight` — на противоположную (если её нет — тупик со шлагбаумом), `uturn` — обратно на своё плечо.

**Центр растёт с дорогой.** `центр = max(16, 4·полос + 8)` метров от середины: 1–2 полосы — 32×32 м, 3 — 40×40, 4 — 48×48.
Стоп-линия на `центр + 5`, переход — `центр + 1 … +4`, плечо не короче `центр + 14`. Кольцо: остров радиусом 12 м (14 м
при двух полосах), кольцевая полоса 5 м, центр = радиус острова + 13 м.

**Маршрут.** Полоса + движение + полоса выезда = ломаная (`geometry.Path`): 80 м подъезда → поворот (квадратичная кривая)
/ разворот (кубическая, ≈ полуокружность) / дуга кольца → выезд. Максимальная скорость в повороте ограничена
`√(3·R)` (не ниже 2.5 м/с): чем круче дуга, тем медленнее. Кузов рисуется по хорде между осями, поэтому длинная машина
срезает поворот, как настоящая. Трамвай и длинные грузовики не разворачиваются: `Path.fits(длина, ширина)` считает,
какую полосу заметает кузов в поворотах (макс. 3.6 м), иначе маршрут для этого типа недоступен.

**Перестроение после перекрёстка.** Если сквозных полос меньше, чем полос выезда, водитель может уйти в соседнюю полосу
(каждая такая пара — отдельный маршрут, вес делится поровну): на «Avenue with U-turn» одна сквозная полоса на две полосы
выезда — «просто вперёд» или «в левую полосу после перекрёстка». Маршруты упорядочены (без пересечения соседних полос).

**Разворот** уходит в полосу выезда так, чтобы между осями было ≥ 8 м (радиус ≥ 4 м): с крайней внутренней полосы — во
вторую полосу выезда. Раскладка отклоняется, если места нет (`полоса + полос выезда < 2`).

## Светофоры: фазы («стадии»)

`layout.stages()` собирает фазы автоматически:

| Условие | Стадии |
|---------|--------|
| ни на одном из противоположных плеч нет левых поворотов / разворотов | одна стадия на пару: N+S, затем E+W (классика) |
| у пары есть левый поворот или разворот | по одной **защищённой** стадии на каждое плечо |

Каждая стадия = зелёный → жёлтый → «всё красное». Правый поворот и движение прямо не пересекают встречный поток, поэтому
не разбивают пару. Вход в следующую стадию только после того, как предыдущая освободила центр (`MAX_ALL_RED_S` = 12 с —
предел ожидания). В адаптивном режиме стадии без очереди пропускаются (`_next_phase`), при потере камеры — FAILSAFE:
фиксированные 20 с на стадию. Ручная программа задаёт лампу каждому плечу (`SignalPhase.arms`), конфликтующие плечи
одновременно открыть нельзя (проверка с сообщением «… open at the same time (collision)»).

**Пешеходы.** Переход плеча закрыт, пока зелёный у самого плеча и у противоположного (его сквозной поток выезжает на
этот переход). Поворачивающие машины уступают пешеходам на переходе, в который поворачивают: если люди на нём идут или
ждут разрешающий сигнал — машина останавливается у перехода; пешеход не выходит, пока на переходе есть машина или она
не успеет остановиться (`_crossing_busy`). Ширина перехода = `4·(полос вх. + полос вых.) + 4` м.

## Дополнительные секции (стрелки)

Полосы уже задают, куда едут (`turns`: налево / прямо / направо / разворот), но раньше светофор был один и тот же
трёхламповый круг на весь съезд, независимо от того, что разрешено конкретной полосе. Теперь у каждого светофора
(`SimTrafficLight.sections`) — по дополнительной секции (стрелке) на каждое поворотное движение, которое реально
использует хотя бы одна полоса съезда; съезд, где все полосы едут только прямо (обычный Crossroads, Tram avenue,
Bus street, кольцо…), секций не получает вовсе — там всё ещё простой круглый светофор.

Состояние секции (`SimulationEngine._light_sections`) всегда не безопаснее физики:

- основной сигнал RED/YELLOW → все секции того же съезда показывают то же самое (весь щит гаснет/переключается разом);
- основной GREEN → стрелка обычно тоже GREEN, но гаснет до RED сама по себе, пока на переходе, в который ведёт этот
  поворот, кто-то идёт или вот-вот шагнёт (тот же `_ped_occupied`, которому уже уступают машины в `_update_vehicles` —
  секция физически не может показать поворот безопаснее, чем он есть).

Ручное управление (`set_light_state`) задаёт основной сигнал как раньше; секции пересчитываются из него автоматически
на той же лампе. По UDP на физический светофор (`smart_intersection/hardware/`) уходит только основной круг — секции
существующий протокол `task_files/traffic_light.py` не поддерживает.

## Пешеходные светофоры

Раньше сигнал «можно переходить» был только числом (`GREEN`/`RED`), пересчитываемым каждый тик, без состояния и
статистики. Теперь у каждого перехода — полноценный управляемый светофор (`PedestrianCrossing.state`,
`.phase_switches`, обновляются в `_update_ped_signals` перед `_apply_lights`, чтобы стрелки уже знали актуальный
переход при принятии решения о своём состоянии в тот же тик):

- ручное управление: `set_ped_light_state(crossing_id, state)` / `POST /pedestrian-lights/{id}/state` (`AUTO` снимает
  принудительное состояние) — так же, как у обычного светофора (Task 9: MANUAL должен уметь принудительно включить
  любой сигнал);
- статистика: `phase_switches` (переключений), `waiting_peds`/`crossing_peds` (сколько ждут / сколько уже идут прямо
  сейчас) — в `get_state()["pedestrian_lights"]`, в XML (`<pedestrianLights>`) и в общей метрике `ped_signal_switches`
  (сумма по всем переходам, отдельно от `phase_switches` обычных светофоров).

## Конфликты внутри центра (зоны)

Вместо клеток или сетки каждая пара маршрутов, которые сближаются меньше чем на 3.8 м (полосы шириной 4 м не считаются),
получает **зону конфликта** — отрезок пути на каждом из маршрутов (`geometry.path_zones`). Внутри зоны одновременно только
одна машина:

- уже находящаяся внутри или не успевающая остановиться проезжает первой;
- иначе уступает та, что ближе к зоне и «младше»: приоритет у тех, кто миновал стоп-линию (тот же рубеж, что и у
  светофора — обогнавший её на зелёный старше того, кто ещё ждёт), затем у более старой машины;
- расстояние до входа в зону — «стена»: машина тормозит по тем же формулам, что и перед красным.

Длинный общий участок (кольцо, слияние в одну полосу выезда) — не зона, а **слияние**: исключительна только входная часть
(8 м), дальше машины едут друг за другом с дистанцией (`_stretch_gap`); после центра — `_exit_gap`. Пока полосы не
пересекаются (параллельные прямые), зоны не строятся вовсе: классический перекрёсток ведёт себя как раньше.

## Готовые типы

| Тип | Что это | Логика |
|-----|---------|--------|
| **Crossroads** | 1 полоса в каждую сторону, только прямо | 2 стадии: N+S, E+W; адаптивный зелёный |
| **T-junction** | 3 дороги, только прямо | стадии N, E+W; тупик с шлагбаумом у отсутствующей дороги |
| **Two-way street** | улица без боковых | одна стадия; светофоры лишь для пешеходов |
| **Tram avenue** | E–W трамвайные пути | трамваи и машины делят переход; трамвай только едет прямо |
| **Bus street** | N–S автобусная полоса | автобусы по полосе, остановки в сцене |
| **Busy junction** | Crossroads под большим потоком с камерой | приоритет плеча N (вес 2), камера смотрит на центр |
| **Turn crossroads** | 2 полосы в каждую сторону: внутренняя — налево, внешняя — прямо и направо | 4 защищённые стадии; лево никогда не встречает встречный поток |
| **No-left crossroads** | то же без левых: прямо / прямо+направо | 2 классические стадии (N+S, E+W); правые поворотчики уступают пешеходам |
| **T-junction with turns** | боковая улица с севера, все движения | 3 защищённые стадии: N, E, W |
| **Roundabout** | остров 12 м, кольцо 5 м, 1 полоса на вход и выход, светофор и переход на каждом плече | 2 стадии (N+S, E+W), как у Crossroads; въезд разрешён только на зелёный, но и тогда уступает кольцу; выезд на любое плечо, включая круг «в разворот»; при загрузке кольца > 50 % входы ждут (нет заклинивания) |
| **Roundabout 2-lane entries** | то же с 2 полосами на входах и выходах | машины стоят на входе бок о бок и сливаются в одну кольцевую полосу |
| **Avenue with U-turn** | проспект E–W: 2+2 полосы = **4 полосы**; внутренняя полоса — налево или разворот, внешняя — прямо (можно уйти в левую полосу после перекрёстка) или направо; боковые улицы 1+1 со всеми движениями | 4 защищённые стадии; камера на мачте 14 м |
| **Boulevard** | 3+3 полосы: налево+разворот / прямо / прямо+направо, боковые 2+2 | центр 40×40 м, 4 стадии, скорость 60 км/ч, камера 16 м |
| **Grand junction** | все плечи 4+4 полосы (налево+разворот, 2 сквозные, прямо+направо) | центр 48×48 м, 4 стадии |

## Проверки

`smart_intersection/tests/test_junctions.py`: рост центра, валидация, маршруты (концы на нужной полосе, гладкость,
скорость в поворотах, доступность разворота по типам), фазы и защищённые стадии, светофоры/пешеходы на широких дорогах,
кольцо (без заклинивания при очень большом потоке), XML с координатами и XSD, API, детерминизм, перезапуск, длинный
прогон и **физические инварианты на каждом типе** при нескольких зёрнах: ни одного пересечения кузовов
(`geo_helpers.run_checks`, SAT по повёрнутым прямоугольникам), ни одного проезда на красный, ни одной остановки на
зелёном дольше 75 с (кроме ожидания пешеходов).

`smart_intersection/tests/test_signals.py`: какие съезды получают секции и какие нет, RED/YELLOW зеркалит основной
сигнал, стрелка гаснет сама при пешеходах на «своём» переходе (и не трогает соседнюю стрелку и основной сигнал),
`run_checks` на съездах с поворотами не портится новой логикой сечений, пешеходные светофоры — состояние, счётчик
переключений (растёт только на настоящей смене, не на каждый тик), счётчики ждущих/переходящих, ручное управление,
`clear_overrides` снимает оба вида принудительного состояния, метрика `ped_signal_switches`, XML (секции и
`<pedestrianLights>` проходят XSD и парсятся один в один с состоянием движка), API (`GET`/`POST /pedestrian-lights`,
секции в `GET /traffic-lights`).

Ограничения: кольцевая полоса всегда одна (две полосы на входе сливаются в неё); переход у кольца стоит на подъездном
плече, а не на самом кольце; защищённые стадии дают более длинный цикл (≈ 36 с на плечо), поэтому средние ожидания выше,
чем на двухфазном перекрёстке.

## Почему у кольца тоже есть светофор

Раздел 1 задачи требует, чтобы система собирала статистику и сама подбирала оптимальные параметры именно светофоров —
поэтому у каждого типа перекрёстка, включая кольцо, должен быть управляемый светофор, иначе оптимизировать нечего.
На кольце светофор — не замена уступанию, а дополнительный уровень: он решает, когда плечу вообще можно попытаться
въехать (метраж потока, приоритет пешеходов, FAILSAFE при потере камеры — всё как на обычном перекрёстке), а уступание
кольцу (`_zone_walls`, `_ring_load`) остаётся физической защитой от столкновений даже на зелёный. Машина никогда не решает
это сама: `update_vehicle` получает состояние светофора только как входной параметр и не может на него повлиять —
изменяет лампу исключительно фазовый механизм (`_apply_lights`), опирающийся на агрегированную статистику очередей и
пешеходов, а не на действия отдельной машины.

## Параллельный вывод на физический светофор

Каждый виртуальный светофор (`TL-N`, `TL-S`, `TL-E`, `TL-W` — по одному на включённое плечо, круговое движение не
исключение) может одновременно выводить своё состояние на настоящий светофор по IP — тот же UDP-протокол LED-матрицы
64×32, что и в `task_files/traffic_light.py` (один кадр RGB на дейтаграмму, `struct.pack("<II", 0, len(frame)) + frame`).
Модуль `smart_intersection/hardware/` (`udp_matrix.py`, `config.py`) — только приёмник уже принятого решения:
`_apply_lights` каждый тик вызывает `hw.send(light.state)` для светофоров, у которых в конфиге указан IP; ничего в эту
сторону обратно не течёт, реальное железо не может повлиять на фазу.

Настраивается в `config/traffic_lights.yaml` (по умолчанию пустой — реальное железо для запуска симуляции не
обязательно, тот же принцип, что у камеры и GPIO, Task 34.11):

```yaml
lights:
  TL-N: {ip: 192.168.1.198, port: 9000}
  TL-E: 192.168.1.199        # порт по умолчанию 9000
```

Путь к файлу переопределяется переменной окружения `SI_LIGHTS_CONFIG` (тот же приём, что и `SI_LAYOUT_DIR`). Отправка
не блокирует тик и не падает, если матрицы нет на месте: `UdpMatrixLight.send` ловит `OSError`, логирует один раз при
потере связи и один раз при восстановлении, дальше молчит. Светофор без записи в конфиге остаётся чисто виртуальным.

Тесты: `smart_intersection/tests/test_hardware.py` — содержимое кадра по состоянию, реальный приём по UDP (два разных
адреса — два независимых кадра), недостижимый адрес не роняет тик, разбор конфига (короткая/длинная запись, пустой
файл, некорректный формат), и главное — присоединённое железо не меняет ни одного решения фазовой машины (совпадение
последовательности состояний с прогоном без железа) и работает как на обычном перекрёстке, так и на кольце.

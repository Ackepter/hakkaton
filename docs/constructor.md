# Конструктор города (режим Build в 3D)

Конструктор встроен в страницу **3D Simulation**. Кнопка **🏗 Build mode** переключает сцену в режим строительства:
симуляция ставится на паузу, слева появляется панель конструктора, вверху — панель инструментов. Правки живут в
локальном черновике (с undo/redo) и попадают в симуляцию по кнопке **✔ Apply** (или **▶ Play**, который применяет и
запускает). Сервис Smart Intersection проверяет раскладку и пересобирает мир.

## Что можно делать

| Вкладка | Возможности |
|---------|-------------|
| **Objects** | ставить здания, дома, деревья, фонари, остановки, скамейки, заборы, киоски и камеры; двигать (перетаскиванием), вращать (`R`), менять размер, высоту, цвет; удалять. У камеры: высота мачты, угол обзора (FOV), дальность, автонаводка на перекрёсток или ручные азимут и наклон; на земле показана область, которую камера видит |
| **Roads** | тип перекрёстка (светофоры / **кольцо**); для каждого из 4 плеч: существует ли дорога, **число полос «к перекрёстку» и «от него» (1–4)**, **стрелки движения каждой полосы (налево / прямо / направо / разворот)**, длина, тип полосы (обычная / автобусная / трамвайный путь), ограничение скорости, пешеходный переход, доля потока |
| **Signals** | режим *Adaptive* (реагирует на трафик, настраиваются зелёный/жёлтый/всё-красное) или *My program*: визуальная программа из блоков «фаза» (лампа для N–S, лампа для E–W, длительность), порядок меняется стрелками, шаблоны, таймлайн цикла. Там, где есть левые повороты / развороты, у каждого плеча своя защищённая фаза — блок показывает по лампе на каждое плечо |
| **Traffic** | интенсивность машин и пешеходов, состав потока (машины, грузовики, автобусы, трамваи, спецтранспорт) |
| **Cities** | имя, сохранение на сервере, загрузка, удаление, **каталог типов перекрёстков с описанием логики**, скачать / загрузить JSON |

Горячие клавиши (Build): `Ctrl+Z` / `Ctrl+Y` — отмена / возврат, `Delete` — удалить выбранное, `R` — повернуть,
`Esc` — инструмент выбора. Правая кнопка мыши вращает камеру, колесо — масштаб.

**Интерактив во время симуляции (Play).** Панель сверху: 🚗 🚚 🚌 🚋 🚑 🚶 — выберите инструмент и кликните рядом с
дорогой, чтобы добавить транспорт или пешехода на ближайшем плече прямо сейчас.

## Правила и проверка

- Декор нельзя ставить на асфальт, перекрёсток и пешеходные переходы: призрак объекта краснеет, сервер проверяет то же
  самое (`tests/test_frontend_geometry.py` сверяет браузерную и серверную проверку на 1500 точках).
- Перетаскивание на дорогу откатывается.
- Программа светофора должна быть безопасной: север–юг и запад–восток не могут быть открыты одновременно, у каждого
  направления должен быть зелёный. Ошибки показываются красным блоком сразу при редактировании.
- Маршрут задаёт полоса: каждая полоса перечисляет разрешённые движения (налево / прямо / направо / разворот), машина
  выбирает одно из них. Прямо по умолчанию; если противоположной дороги нет, это тупик с шлагбаумом. Повороты и
  развороты разрешены только на существующие дороги; трамвай и длинные грузовики не разворачиваются и не берут крутые
  дуги (`Path.fits`). Разворот требует места: полоса номер `i` + число полос «от перекрёстка» ≥ 2.
- **Центр растёт:** `центр = max(16, 4·полос + 8)` м от середины (1–2 полосы: 32×32 м, 3: 40×40, 4: 48×48). Плечо должно быть не
  короче центра + 14 м; конструктор удлиняет плечи и убирает декор, оказавшийся на новом асфальте (Ctrl+Z возвращает).
- Пешеходы переходят плечо, только пока его светофоры красные достаточно долго и машины ушли с перехода; в режиме
  «программа» это проверяется по последовательности фаз.

## Формат раскладки (JSON)

```json
{
  "version": 1, "name": "My city",
  "junction": "signal",
  "arms": {"north": {"enabled": true, "length_m": 80, "lane_type": "mixed", "speed_limit_mps": 13.9,
                     "crossing": true, "weight": 1.0,
                     "lanes_in": 2, "lanes_out": 2,
                     "turns": [["left", "uturn"], ["straight", "right"]]},   // по одному списку на полосу, 0 = у осевой
           "south": {}, "east": {}, "west": {}},
  "signal": {"mode": "fixed", "base_green": 30, "min_green": 8, "max_green": 60, "yellow": 3, "all_red": 3,
             "program": [{"name": "NS green", "ns": "GREEN", "ew": "RED", "duration": 30}]},
  "traffic": {"spawn_rate": 12, "ped_spawn_rate": 5, "type_probs": {"car": 0.75, "truck": 0.1}},
  "scenery": [{"id": "tree-1", "type": "tree", "x": 30, "z": 30, "rotation_deg": 0, "scale": 1}],
  "cameras": [{"id": "CAM-A", "x": -28, "z": -28, "height_m": 14, "fov_deg": 70, "radius_m": 90,
               "yaw_deg": null, "pitch_deg": null, "enabled": true}]
}
```

Схема и проверки: `smart_intersection/layout.py`. Раскладки хранятся файлами `config/layouts/<имя>.json`
(каталог задаётся `SI_LAYOUT_DIR`); последняя применённая запоминается и восстанавливается при перезапуске.

## API (Smart Intersection, порт 8001)

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/layout` | текущая раскладка |
| PUT | `/layout` | применить (422 со списком причин, если раскладка недопустима); симуляция останавливается и пересобирается |
| POST | `/layout/validate` | проверить без применения |
| GET | `/layout/presets` | готовые раскладки (6 классических и 8 новых типов, см. [junctions.md](junctions.md)) |
| GET | `/layout/junction-types` | каталог типов: название, вид (`signal` / `roundabout`), описание логики |
| GET | `/geometry` | геометрия дороги текущей раскладки (центр, полосы, переходы, столбы светофоров) — для камеры и рендереров |
| GET / POST | `/layouts` | список сохранённых / сохранить |
| GET / DELETE | `/layouts/{name}` | загрузить / удалить |
| POST | `/simulation/spawn` | `{kind: vehicle, arm, type, lane?, movement?}` или `{kind: pedestrian, crossing}` — добавить сейчас |

## Камеры в раскладке

Камера из конструктора — виртуальная камера-«обскура»: позиция мачты `x, z`, высота `height_m`, угол обзора по горизонтали
`fov_deg`, дальность `radius_m` и направление (`yaw_deg` — азимут, 0 = север; `pitch_deg` — наклон вниз; `null` = навестись на
центр перекрёстка). На земле показана область, которую она видит. После Apply основной бэкенд синхронизирует свои камеры
(`POST /api/vision/sync-layout`): каждая камера получает перспективную картинку, детекции и зоны полос и переходов только
тех, что реально попадают в её кадр (по одной зоне на камеру, без двойного счёта). Без камер в раскладке работает камера
по умолчанию (над серединой перекрёстка, обзор 100°) из `config/cameras.yaml`. Подробнее: [cameras-and-vision.md](cameras-and-vision.md).

## Как это устроено

```
Frontend (draft + undo) ──PUT /layout──► SI: validate_layout ──► build_world(layout) ──► SimulationEngine
        │                                          │
        └── POST /api/vision/sync-layout ──► backend: камеры и зоны по раскладке
```

- Мир (`engine/world.py`) строит полосы, светофоры и переходы только для существующих плеч; короткое плечо задаёт точку
  появления (`spawn_pos`), скорость появления ограничена расстоянием до стоп-линии, чтобы машина успела остановиться.
- Маршруты (`geometry.py`) — ломаные «80 м до центра → поворот / разворот / дуга кольца → выход»; машина хранит длину
  пути `s`, а движок сам публикует её положение `x, z, heading` (в XML тоже), поэтому 3D, камера и Dashboard не считают
  геометрию по-своему.
- Программа светофора исполняется дословно; адаптивный режим использует параметры раскладки.
- Тип полосы переопределяет состав потока на этом плече; вес плеча меняет долю прибытий.

## Тесты

```bash
pytest smart_intersection/tests/test_layout.py      # модель, проверки, хранилище, мир, физика на пресетах и программах
pytest tests/test_frontend_geometry.py              # браузерная и серверная геометрия (центр, полосы, камера) совпадают
pytest smart_intersection/tests/test_junctions.py   # полосы, повороты, развороты, кольцо, зоны конфликтов, физика на всех типах
pytest tests/test_vision_sync.py                    # камеры из раскладки
pytest tests/test_e2e_builder.py                    # настоящий Chrome управляет конструктором (порты 8000/8001/5173)
```

UI-тест пропускается, если нет Chrome/Edge, `node_modules` или заняты порты 8000/8001/5173.
